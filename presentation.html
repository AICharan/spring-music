Key Architecture Decisions

ADR-001: Strangler Fig

New services run alongside the monolith. One routing rule = instant rollback. No code change required for rollback.

Rejected: big-bang rewrite (zero trust in feature parity)

ADR-002: ACL Pattern

AlbumPayload is the only shared contract. AlbumTranslator is the ONLY place the two representations meet. 

Album (monolith JPA)
  ↕ AlbumPayload (ACL)
AlbumEntity (service JPA)

ADR-003: Dual-Write

Current: @TransactionalEventListener after commit → HTTP relay. At-most-once. Event may be lost.

Prescribed: Outbox pattern — event written to DB in same transaction. No Kafka needed.

ADR-004: Independent CI

Path-filtered GitHub Actions. A broken monolith does NOT block album-service deployment. 

monolith.yml    → src/**
album-service.yml → album-service/**
recommendation.yml → recommendation-service/**

The Contract Test Insight

Monolith (documented quirk)

GET /albums/nonexistent-id
→ HTTP 200
→ body: ""  (empty string)

AlbumController.getById() returns null → Spring serialises as empty response

album-service (correct REST)

GET /albums/nonexistent-id
→ HTTP 404
→ body: (none)

ResponseEntity.notFound().build() — correct semantics

The contract test surfaced this divergence and documented it rather than hiding it. The monolith's quirk is pinned by a characterization test. The fix (@ResponseStatus(NOT_FOUND)) is in the "If We Had Another Day" list — safe to ship without breaking anything.

How We Used Claude Code

What saved the most time

  • Full codebase scan in one pass — all quirks enumerated before writing a test
  • ADR drafting from a decision question — trade-off analysis in seconds
  • 3 services + 3 CI pipelines + runbook in one session
  • Two-sided contract test structure — surfaced the 404 vs 200 divergence automatically

What surprised us

  • Claude Code suggested @TransactionalEventListener unprompted as safer than a plain @EventListener
  • CLAUDE.md doubles as a living ADR store — future sessions have full context
  • Characterization tests are better written by asking "what are the quirks" than "write tests for this code"
  • The runbook's 3am decision tree was the fastest file to write — Claude understands ops scenarios

If We Had Another Day

  1. Outbox pattern — replace at-most-once relay with guaranteed at-least-once delivery (H2 outbox table, no Kafka)
  2. Docker Compose — one command to start all three services; data migration runs automatically
  3. API Gateway — nginx config to implement the strangler fig routing rule (5% → 50% → 100%)
  4. Fix the 404 quirk — @ResponseStatus(NOT_FOUND) on monolith's getById; update characterization test to expect 404; both services aligned
  5. Platform info service — extract InfoController + CF detection; remove java-cfenv-boot from the album domain
